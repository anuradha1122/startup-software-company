# IT Hub — Project Overview

## Stack

- Laravel 13
- PHP 8.4+
- React 19
- TypeScript
- Inertia 3
- Tailwind CSS
- MySQL
- Pest

## Purpose

Internal software-company ERP / PSA system managing:

Lead → Client → Requirement → Estimate → Proposal →
Quotation → Contract → Project → Work → Cost →
Invoice → Payment → Profitability → Support.

## Development Rule

Each module must be completed with its applicable:

- Backend
- React UI
- permissions
- validation
- database
- PDF
- Excel
- notifications
- emails
- tests
- documentation

before moving to the next module.

## M05

M05 establishes the transition from signed commercial agreement to
governed software project.

A project inherits its commercial and scope baseline from the signed
contract and cannot redefine that baseline.

## M06

M06 adds project execution workflow.

Work originates inside an active M05 project and is organized through
tasks, workflow statuses, dependencies, work submissions and formal
review.

## M07

M07 formalizes operational people, skills and project staffing.

Users become eligible M06 task assignees only while they hold an
active assignment on the relevant project.

HR employment administration remains outside this module and is
reserved for M15.

## M08

M08 records actual project work time and converts approved hours into
private internal project cost.

Time entries reference M06 tasks and M07 project assignments.

Internal cost information is never client-facing.

## M09

M09 manages project non-labor expenses and supplier costs.

Approved M09 costs combine with approved M08 labor costs in M11
project profitability.

## M10

M10 manages client invoices, payment recording and accounts receivable.

Invoices may contain manually entered service lines or explicitly
imported approved M09 billable expenses.

Payments are separately recorded and allocated against outstanding
invoices.

## M11

M11 consolidates project financial information from M05, M08, M09 and
M10.

It provides internal project profitability, cost, billing, collection,
receivable and margin reporting.

M11 financial information is strictly internal.

## M12

M12 introduces a separate authenticated client portal.

Client users can access only explicitly client-safe project information,
published documents, issued invoices and client approval requests.

Internal finance, costing, profitability, supplier and workforce data
remain outside the portal security boundary.

## M13

M13 provides centralized internal reporting, export discovery, report
run auditing and administrative operational health monitoring.

It consolidates data from earlier modules without duplicating their
transactional records.

## M14

M14 introduces support ticket management and formal project change
requests.

Support tickets may originate internally or from authenticated M12
client portal users.

Change requests provide controlled scope-change submission, estimation,
review and optional conversion into M06 delivery work.

## M15

M15 introduces internal HR, employee records, leave management,
attendance and payroll.

M15 payroll and salary information is confidential.

M15 remains separate from M07 operational resource management and M08
internal project costing.
